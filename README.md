# HinkChat

> 端到端加密 · 零服务器 · 纯 P2P 聊天应用
>
> 密钥离线生成，全程不上传网络

---

## ✨ 特性

- ⚡ **闪电般快速** — 直连 P2P 传输，不经过任何中间服务器
- 🔒 **端到端加密** — ECDH 密钥交换 + AES-256-GCM 加密，零知识架构
- 👥 **支持群聊** — 多人加密聊天，Mesh 架构消息同步广播
- 💻 **纯前端** — 单 HTML 文件，打开即用，无需部署后端
- 📱 **响应式** — 完美适配桌面端和移动端
- 💾 **本地存储** — 聊天记录和密钥保存在本地，隐私完全可控

## 🚀 快速开始


将 `index.html` 推送到 GitHub 仓库，启用 Pages 功能即可在线使用。

## 📖 使用指南

### 一对一私聊

1. **A 端**：打开应用 → 输入昵称 → 自动生成连接码
2. **A 端**：点击「📋 复制连接码」，通过任意渠道发送给 B（微信/QQ/邮件等）
3. **B 端**：打开应用 → 输入昵称 → 在「粘贴对方的连接码」处粘贴 → 点击「确认连接」
4. **B 端**：自动生成应答码 → 复制后发送回 A
5. **A 端**：粘贴应答码 → 点击「确认连接」
6. ✅ 连接建立！开始端到端加密聊天

> 💡 **提示**：连接码和应答码都是一次性的，建立连接后无需再次交换。
> 密钥只在各自浏览器中生成，永远不会上传网络。

### 群聊使用

1. 点击左侧「👥」按钮创建群聊
2. 输入群聊名称 → 创建
3. 逐个添加群成员（先通过私聊与每个人建立连接）
4. 在群聊中发送的消息会加密广播给所有在线成员

> 🔐 **群聊加密说明**：群聊采用 Mesh 架构，每条消息会通过你与每位成员的独立加密通道发送。
> 每个一对一连接都有独立的共享密钥，安全性等同于私聊。

## 🏗️ 技术架构

### 整体架构图

```
┌─────────────┐                    ┌─────────────┐
│   浏览器 A   │                    │   浏览器 B   │
│             │  WebRTC DataChannel │             │
│  ECDH 密钥对 │◄──────────────────►│  ECDH 密钥对 │
│             │  加密消息 (AES-GCM) │             │
│  AES-GCM 加密│◄──────────────────►│  AES-GCM 解密│
│             │                    │             │
└─────────────┘                    └─────────────┘
          │                                  │
          └────────── STUN 服务器 ───────────┘
              (仅用于 NAT 穿透，不传输数据)
```

### 加密流程

```
步骤 1：密钥生成（双方各自本地生成）
  ├── ECDH P-256 密钥对生成
  ├── 私钥：永不离开浏览器
  └── 公钥：随连接码一起发送

步骤 2：密钥交换（通过连接码/应答码）
  ├── A 生成 Offer（含公钥 + WebRTC SDP）
  ├── B 收到 Offer → 派生共享密钥
  ├── B 生成 Answer（含公钥 + WebRTC SDP）
  └── A 收到 Answer → 派生共享密钥

步骤 3：密钥派生（HKDF）
  ├── 输入：ECDH 协商出的 256-bit 共享密钥
  ├── Salt: "HC-v1"
  ├── Info: "AES-256-GCM"
  └── 输出：AES-256-GCM 加密密钥

步骤 4：消息加密
  ├── 生成 12 字节随机 IV
  ├── AES-256-GCM 加密（含认证标签）
  ├── IV + 密文 + 认证标签 → Base64
  └── 通过 WebRTC DataChannel 发送

步骤 5：消息解密
  ├── Base64 解码 → 分离 IV 和密文
  ├── AES-256-GCM 解密 + 认证验证
  └── 验证失败则丢弃消息
```

### 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| **UI** | 原生 HTML + CSS + JS | 零依赖，单文件 |
| **加密** | Web Crypto API | 浏览器原生加密接口 |
| **密钥交换** | ECDH (P-256) | 椭圆曲线迪菲-赫尔曼 |
| **密钥派生** | HKDF (SHA-256) | 基于 HMAC 的密钥派生函数 |
| **对称加密** | AES-256-GCM | 256 位密钥 + Galois/Counter 模式 |
| **传输** | WebRTC DataChannel | P2P 数据通道，可靠有序 |
| **NAT 穿透** | STUN | Google 公共 STUN 服务器 |
| **存储** | localStorage | 本地持久化 |

### 安全特性

- ✅ **前向安全**：每次连接生成新密钥对，互不影响
- ✅ **认证加密**：AES-GCM 同时提供机密性和完整性
- ✅ **零知识架构**：服务器无法解密任何消息内容
- ✅ **密钥隔离**：私钥永不出浏览器内存
- ✅ **防篡改**：GCM 模式自动验证消息完整性

## 🔧 核心模块说明

### Crypto 模块

负责所有密码学操作：

- `generateKeyPair()` — 生成 ECDH P-256 密钥对
- `deriveSharedKey(peerPubKey)` — 基于对方公钥派生共享密钥
- `encrypt(key, text)` — AES-256-GCM 加密
- `decrypt(key, ciphertext)` — AES-256-GCM 解密

### PeerConnection 类

封装 WebRTC 连接逻辑：

- `createOffer()` — 创建 Offer SDP + 公钥
- `createAnswer(offer)` — 处理 Offer 并生成 Answer
- `applyAnswer(answer)` — 应用 Answer 建立连接
- `sendEncrypted(text)` — 发送加密消息
- `decryptMessage(data)` — 解密收到的消息

### 连接码格式

连接码（Offer）和应答码（Answer）均为 JSON 格式字符串：

```json
{
  "type": "offer",
  "sdp": "...",
  "pub": "...",
  "name": "Alice"
}
```

| 字段 | 说明 |
|------|------|
| `type` | 类型：`offer` 或 `answer` |
| `sdp` | WebRTC SDP 会话描述协议 |
| `pub` | ECDH 公钥 (Base64 raw 格式) |
| `name` | 用户昵称 |

## ❓ 常见问题

### Q: 为什么连接码这么长？

连接码包含了 WebRTC 的 SDP 信息（媒体能力、ICE 候选等）和 ECDH 公钥。这是 P2P 连接必需的握手信息。未来版本会考虑压缩优化。

### Q: 对方收不到消息怎么办？

1. 确认双方都保持页面打开
2. 检查网络环境（某些严格的企业网络可能阻止 WebRTC）
3. 尝试使用手机热点测试
4. 刷新页面后重新建立连接

### Q: 聊天记录存在哪里？

所有聊天记录和密钥都保存在浏览器的 `localStorage` 中，只在你本地设备上。清除浏览器数据会丢失所有记录。

### Q: 支持文件传输吗？

目前仅支持文本消息。文件传输功能正在规划中。

### Q: 安全吗？会被破解吗？

使用的是行业标准的密码学算法（ECDH P-256 + AES-256-GCM），均由浏览器原生 Web Crypto API 实现，安全性有保障。只要你的私钥不泄露，第三方无法解密消息。

### Q: 为什么叫 HinkChat？

UI 设计风格参考了 [hink.uk](https://hink.uk) 的极简美学，因此命名为 HinkChat。
